# MVP биллинга контейнерной площадки ЛКДС

Локальное приложение для оформления услуг контейнерной площадки: поставка КТК, вывоз, возврат, учёт собственников, начисления и счета на оплату. Репозиторий — [airafka/bil](https://github.com/airafka/bil), общая ветка — **main**. Название локальной папки bil-next не является названием ветки.

Документация сверена с кодом 10.11.2026. На этом компьютере также проверены frontend HTTP 200, backend UP, работающие контейнеры billing-next и схема Flyway V28. Это результат проверки на указанную дату, а не постоянная гарантия состояния окружения.

## Окружение

Параметры по умолчанию заданы в [compose.yaml](compose.yaml) и [.env.example](.env.example); локальный .env может менять порты.

| Компонент | Адрес / имя |
| --- | --- |
| Compose-проект | billing-next |
| UI | http://localhost:3001 |
| Backend / health | http://localhost:8081 / http://localhost:8081/actuator/health |
| PostgreSQL | localhost:5433, база billing_next, пользователь billing |
| Контейнеры | billing-next-frontend-1, billing-next-backend-1, billing-next-db-1 |
| Хранилище PostgreSQL | billing-next_postgres-data |

На текущем компьютере рабочий каталог: C:\Users\Пользователь\Documents\ChatGPT\Билинг\bil-next. На другом компьютере путь может отличаться; все команды выполняются из корня его клона. Исходная локальная копия «Билинг 2.0» и её окружение billing удалены на этом компьютере и для запуска не нужны.

Для уже настроенной копии: запустить Docker Desktop, затем выполнить .\start.ps1. Остановка — .\stop.ps1. Скрипт запуска пересобирает приложение, остановка сохраняет БД. Для нового компьютера **сначала восстановите снимок в пустую БД**, затем запускайте приложение: [пошаговая инструкция](database/README.md).

## Услуги и разделы

В рабочей БД на дату сверки три услуги:

- «Комплексная услуга по приему контейнера в составе поезда».
- «Комплексная услуга по приему контейнера при повагонной отправке».
- «Комплексная услуга по приему контейнера, прибывшего автотранспортом».

Первые две выбираются при создании ЖД-услуги независимо от количества КТК. Автоуслуга создаётся при оформлении возврата на другую пару клиент/договор; это не отдельный вариант первоначального ЖД-мастера. Подробности расчёта — в [бизнес-логике](BACKEND_ALIGNMENT.md).

## Код и проверки

- Frontend: React, TypeScript, React Router, Vite; зависимости фиксирует [package-lock.json](frontend/package-lock.json).
- Backend: Java 21, Spring Boot 4.1.0, Spring JDBC, Bean Validation.
- БД: PostgreSQL 16, Flyway; активный каталог миграций — [db/baseline](backend/src/main/resources/db/baseline), V1–V28.
- Сборка и запуск: Docker Compose; frontend раздаёт Nginx.

[Backend Dockerfile](backend/Dockerfile) выполняет Maven package с тестами; [frontend Dockerfile](frontend/Dockerfile) — ESLint, Vitest и TypeScript/Vite build. Локально: mvn test из backend; npm ci, npm run lint, npm run test, npm run build из frontend. Для frontend dev доступен npm run dev.

При запуске backend вне Compose необходимо явно настроить DB_HOST=localhost, DB_PORT=5433, DB_NAME=billing_next и локальные учётные данные: значения по умолчанию в application.yml ещё указывают на billing:5432. Для тестов используйте отдельную БД и свободный порт.

Проверки, меняющие данные, выполняются только в изолированной тестовой БД. Старые scripts могут содержать прежние пути и порты: перед запуском читать сценарий. Количество ранее пройденных тестов не является текущим результатом — после задачи сообщать только реально выполненные проверки.

## Границы MVP

Интеграции с ЭТРАН, TOS, Datareon и 1С не подключены. Накладные создаются локально, складские события фиксируются ручным выполнением заявок. Оплата счёта — локальная отметка, без банковского обмена. Данные генератора демонстрационные.

Git синхронизирует код и опубликованный файл снимка, но не работающие базы двух компьютеров. Порядок публикации кода — в [AGENTS.md](AGENTS.md), порядок работы с данными — в [database/README.md](database/README.md).
