# Стандарт интерфейса MVP

Общие правила сверены с кодом 10.11.2026; таблица КТК ЖД-поставки и редактор накладных повторно сверены 16.11.2026. Применяется к созданию, просмотру и редактированию. Образцы действующих компонентов: http://localhost:3021/ui-kit. Страница образцов не создаёт бизнес-документы.

## Безномерный вывоз

В ЖД-вывозе поле «Наличие номеров» показывает «Заданы номера вагонов и КТК». На шаге «Вагоны» выбирают номера вагонов, на шаге «КТК» — номера контейнеров для каждого вагона. В безномерном автовывозе количество равно одному. После выбора типоразмера поле «Собственник КТК» показывает клиентов и свободный остаток. В черновике собственника можно изменить. В подтверждённой заявке кнопка «Отправить пакет TOS» открывает список свободных КТК планового собственника и типоразмера. Оператор выбирает один КТК из списка. Поиск по номеру и переход между страницами помогают найти нужную строку. Для отправки нужен выбранный КТК. В ранее подтверждённых заявках без планового собственника список показывает свободные КТК нужного типоразмера с их текущими собственниками. [Обработка пакетов](BACKEND_ALIGNMENT.md#входящие-результаты-tos).

## Паттерны и реализация

Предоставленные архивы frontend основной системы и Alabuga UI Kit использовались как ориентир. MVP реализует собственные компоненты; пакет @alabuga/uikit не подключён в [package.json](frontend/package.json). Названия паттернов не означают наличие одноимённых библиотек в проекте.

| Ориентир | Применение в MVP |
| --- | --- |
| pageWithSlide | Боковые формы рейса через AppOverlay; основные карточки имеют отдельные маршруты |
| tableUI | Общие table-system.css, responsive-tables.css, RecordRow, RowActions |
| groupedTable | RailwayReceivingHierarchy, WaybillCompositionTable и другие таблицы накладная → вагон → КТК |
| tableedit | Изменение полей внутри тех же ячеек без перестройки колонок |
| Iformv2 | FormControls, общие группы полей и горизонтальные подписи |
| Alabuga UI Kit | Общие токены оформления и адаптированные элементы управления |

В текущем MVP нет универсального pageWithSlide для всех карточек. Настройка колонок пользователем не нужна и не добавляется. Используются существующие поля и сценарии MVP, а не все возможности основной системы.

## Календарь MVP

В шапке перед пользователем находится общий календарь ApplicationCalendar: текущая дата, нативное поле даты, предыдущий/следующий день, «Применить» и «Сегодня». На узком экране скрывается префикс «Дата MVP:», дата остаётся видимой. Всплывающая форма ограничена экраном, закрывается снаружи и по Escape; ошибки показываются внутри. На время сохранения действия блокируются.

ApplicationClockProvider загружает дату до открытия форм, обновляет её при возврате на вкладку и каждые 15 секунд в видимой вкладке; BroadcastChannel сообщает об изменении соседним вкладкам. Конфликт версий не затирает чужой выбор: календарь обновляется и показывает ошибку. Смена даты сразу обновляет выборку периодов в отчёте хранения и дату создания в мастере комплексной заявки. Плановая дата новых поставок/вывозов и дата рейса во всех трёх способах создания подставляются из календаря MVP, время — из серверного clock.now в Europe/Moscow. Пока поле не изменено, оно следует рабочему календарю; ручной ввод и очистка сохраняются при обновлении календаря. Повторное открытие боковой формы нового рейса получает актуальную дату. Сохранённые даты при редактировании, срок ремонта вагона и дата действия договора не заменяются текущей датой. Передача даты рейса и заполнение её редактора используют Europe/Moscow независимо от часового пояса браузера. Уже введённые реквизиты открытой формы сохраняются. Правила времени и хранения настройки — в [backend](BACKEND_ALIGNMENT.md#рабочая-дата-и-время).

При смене рабочей даты открытая карточка черновика вывоза обновляет собственников у существующих и добавляемых КТК. Это работает для авто и ЖД. Введённые реквизиты, ЗПУ, груз и несохранённые добавления сохраняются. Пока загружаются сведения на новую дату, карточка показывает «Загрузка…». При ошибке доступна кнопка «Повторить». Карточка игнорирует ответы для прежней даты или состава. Подтверждённые и выполненные вывозы показывают зафиксированных собственников.

[Браузерная проверка черновика](scripts/draft-owner-calendar-ui.cjs) охватывает авто и ЖД, смену даты во время редактирования и повтор после ошибки. Запустите тестовый frontend на `127.0.0.1:5173` и выполните `node scripts/draft-owner-calendar-ui.cjs` из корня репозитория. Сценарий подставляет ответы API внутри Chrome. Путь к браузеру можно указать в `CHROME_EXE`.

Проверка дат: [calendar-forms-ui.cjs](scripts/calendar-forms-ui.cjs) работает только через отдельный frontend на 3203, backend billing-next-stock-history-test и БД billing_stock_history_test. Проверяет даты новых заявок и всех форм рейса, ручной ввод/очистку, дату комплексной заявки, сохранение и редактирование рейса при часовом поясе браузера America/Los_Angeles. Сценарий создаёт тестовые документы и возвращает исходную настройку календаря. На рабочем окружении изменяющие проверки не выполняются.

## Карточки, действия и формы

Этапы создания заявки и накладной отображает общий [CreationSteps](frontend/src/components/CreationSteps.tsx): текущий этап выделен, предыдущие доступны, следующие заблокированы. Проверка заполнения и переходы остаются в формах; компонент получает подписи, текущий номер этапа и обработчик выбора.

В [domain.ts](frontend/src/domain.ts) общие реквизиты списка и карточки заявки описывает OrderHeaderFields, общие поля груза накладной — WaybillProductFields. Публичные типы дополняют их своими полями с сохранением обязательности и допустимых NULL.

Реестры ведут в карточки по маршрутам [App.tsx](frontend/src/App.tsx). Общие действия строки — RowActions; RecordRow открывает карточку двойным щелчком, не перехватывая вложенные интерактивные элементы.

Белая рабочая область объединяет вкладки и содержимое. Реквизиты располагаются в две колонки на широком экране и в одну на узком. Просмотр показывает текст, редактирование — поля в той же структуре.

- Основные действия, сохранение, отмена и закрытие — сверху; нижние дубли не добавлять.
- Редактирование — карандаш с доступной подписью, закрытие — крестик.
- Связанные документы открываются ссылкой на номер документа.
- Создание в реестре — «+ Создать»; удаление — действие строки.
- Вкладки при нехватке ширины прокручиваются.
- Необязательные поиск и фильтры не показывать. Клиент, договор, станции и плательщик накладной остаются реквизитами, определяющими документ.

Боковая форма рейса имеет ширину 640 px с ограничением экраном. Заполняемые реквизиты: дата/время, для авто также перевозчик, водитель, ТС, затем комментарий. В формах создания рейса из заявки рядом с сохранением есть «Автозаполнить»: для авто выбирается первая активная запись каждого незаполненного справочника перевозчика/водителя/ТС, пустая дата получает дату и время календаря MVP. Введённые значения и комментарий сохраняются; ЖД не запрашивает автологистику. При нехватке справочников выводится ошибка без частичного заполнения. Кнопка только заполняет форму, создание выполняется отдельным действием. Во время загрузки повтор, сохранение и закрытие блокируются. В этой форме нет лишнего заголовка «Логистика» и справочного блока. Формы выводятся через [AppOverlay](frontend/src/components/AppOverlay.tsx), вне ячеек таблиц и родительских form.

## Отмена транспортных заявок и рейсов

Действия «Отменить заявку» и «Отменить рейс» находятся сверху карточки, вне режима редактирования. Используется общая боковая форма через AppOverlay и нативный dialog: причина не запрашивается, начальный фокус устанавливается на закрытие формы, Escape закрывает форму до начала сохранения. Во время запроса повторная отправка блокируется. Ошибки складских операций остаются в форме.

После отмены статус — «Отменено», редактирование и выполнение недоступны. Причины отмены и отдельный запрос их получения отсутствуют. Состав отменённой ЖД-поставки после освобождения накладной может быть недоступен; архив состава не ведётся. В истории КТК обратный переход помечается «Отмена».

## Очистка операционных данных

В шапке локального MVP отдельная кнопка «Очистить заявки», если функция включена на сервере. Боковая форма через AppOverlay и native dialog показывает полный состав удаления и количества, объясняет сохранение справочников и резервной копии. Удаление доступно только после точного ввода УДАЛИТЬ. Начальный фокус — закрытие; Escape закрывает до отправки. Пока выполняется запрос, закрытие и повторная отправка блокируются. При изменении данных или ошибке нужно обновить список и повторно ввести подтверждение. После успешной очистки «Готово» открывает заново пустой отчёт хранения. Фильтры отчёта не ограничивают удаление. Правила хранения копий — в database/README.md.

## Таблицы

Сохранять table/thead/tbody, colSpan/rowSpan и иерархию на любой ширине. На узком экране прокручивается рамка таблицы, не вся страница. Строки не превращаются в карточки. Выбор собственника остаётся внутри ячейки КТК.

Геометрию задают [useResponsiveTables](frontend/src/components/useResponsiveTables.ts) и [tableGeometry](frontend/src/components/tableGeometry.ts). Числовые colgroup задают минимумы и пропорции; свободная ширина распределяется между колонками данных, служебные остаются компактными. Таблица заполняет рамку. Режим редактирования не меняет структуру.

В таблице КТК ЖД-поставки ширины колонок заданы числовым colgroup: номер КТК остаётся одной строкой, массы и признаки занимают компактные столбцы, собственник и статус могут переноситься по словам. Отступы иерархии относятся к заголовкам накладной и вагона; номер КТК выровнен с заголовком своего столбца. Режимы просмотра и редактирования используют одинаковую геометрию. На широком экране видны все столбцы, при недостатке места прокручивается только рамка таблицы.

Не использовать измерения уже отрисованных ячеек как новые исходные размеры. ResizeObserver обновляет доступность прокрутки, а не переписывает ширины на каждом кадре анимации. При масштабе 90% проверять реальный scrollLeft: округлённое сравнение scrollWidth/clientWidth может скрыть лишнюю прокрутку.

Короткие действия, включая «Создать рейс», остаются в одну строку. Длинные значения переносятся в ячейке; не назначать nowrap всей таблице. Выбор строк — флажками, общий выбор — флажком заголовка. В выборе рейса не требуется заливать выбранную строку.

Редактор груза автозаявки задаёт числовые ширины colgroup: № 44, код ЕТСНГ 240, наименование 320, масса 180, действия 44 px. Служебные колонки сохраняют ширину 44 px, свободное место распределяется между тремя колонками данных. Минимальная ширина 828 px; на узком экране прокрутка остаётся внутри таблицы. Сворачивание КТК и добавление строк груза не меняют сетку.

## Собственники в ЖД-поставке

После «Накладные ЭТРАН» и «Вагоны» собственник каждого КТК выбирается непосредственно в иерархической таблице. Выбор сохраняется при переходе между шагами; запись выполняется при создании заявки. В существующей поставке обычное редактирование по карандашу сохранено.

Массовое назначение собственника КТК:

1. Кнопка «Изменить собственника КТК» справа открывает выбор КТК и одиночный список клиентов.
2. Пока не выбраны КТК и клиент, применение недоступно. Предыдущее или общее значение собственника не подставляется в этот список.
3. Повторное нажатие той же кнопки применяет выбор; отдельной кнопки «Применить» нет.
4. Выбор вагона/накладной включает свёрнутые строки, частичный выбор показывает промежуточный флажок.
5. В просмотре черновика сохраняется сразу; в режиме редактирования и мастере — вместе с документом. Успех закрывает режим, ошибка сохраняет выбор.

## Смена собственника в разделе «Заявки»

Пункт «Смена собственника» открывает реестр передач КТК. В этот же реестр ведёт кнопка на странице «Остатки и собственники КТК».

В новой заявке выберите прежнего и нового собственников. Пустой черновик можно сохранить и заполнить позднее. Для подтверждения нужен хотя бы один КТК. «Дата передачи» по умолчанию равна рабочей дате и следует календарю до ручного ввода. При будущей дате поле «Собственник на сегодня» показывает, у кого КТК числится в остатках на текущую рабочую дату. Для сегодняшней и прошедшей дат подбираются КТК прежнего собственника на дату передачи. Изменение собственника или даты в форме сбрасывает выбор КТК. В сохранённом черновике прежний собственник закреплён. Нового собственника, дату и состав КТК можно изменить за одно сохранение.

На вкладке КТК доступны свободные контейнеры, у которых строка приёмки получила `FINISHED`. Дата передачи может совпасть с днём фактической приёмки текущего визита или быть позднее. КТК с резервом на вывоз и КТК в другом черновике передачи исключаются из подбора. Если в старом черновике были КТК разных прежних собственников, подберите состав одного собственника с учётом даты заявки.

Флажок «Дата будущая» в черновике разрешает выбор будущего дня. При снятом флажке доступны сегодня и прошедшие дни. Подтверждённая будущая заявка показывает «Ожидает выполнения» и разрешает окончательную отмену. После обновления остатка статус становится «Выполнено». Реестр и карточка обновляют статус каждые пять секунд в видимой вкладке. Даты подтверждения и доставки показаны в UTC.

На вкладке «КТК» каждый период визита занимает отдельную строку в таблице «КТК», «Тип заявки», «Номер заявки», «Дата события, МСК», «Собственник КТК». В строке поставки указан собственник конкретного КТК при приёмке, в строке смены — получатель передачи по этой заявке. Поставка и смены собственника идут по времени события. Номер заявки открывает документ. Запланированная передача помечена рядом с типом заявки. Номер КТК и флажок подбора общие для всех строк одного контейнера. При подборе используются периоды открытого визита, а при просмотре сохранённого состава — периоды визита, закреплённого за строкой. Несколько передач одного дня показаны по отдельности. Пустая ячейка обозначена прочерком.

## Навигация, загрузка и уведомления

Меню при загрузке свёрнуто; раскрытое состояние не сохраняется. Иконка раскрывает свою группу; выбор пункта или логотипа сворачивает меню. Настольная раскрытая панель — 280 px; до 640 px используется нижняя навигация. Верхней кнопки со стрелкой нет.

Раскрытие и сворачивание, в том числе при переходе между разделами, используют 240 мс ease-out. Скрытые пункты inert и aria-hidden. Наведение/фокус предварительно загружают модуль страницы, но не её API-данные.

[TableReveal](frontend/src/components/TableReveal.tsx) скрывает содержимое реестра до завершения запроса и показывает «Загружаем данные…». После ответа таблица проявляется за 520 мс; пустой результат и ошибка также завершают загрузку. Геометрия не анимируется. Для prefers-reduced-motion анимации отключаются.

Общий [HTTP-клиент](frontend/src/http.ts) объединяет одинаковые одновременно выполняемые обычные GET; завершённые ответы не кэширует. Изменяющие запросы сбрасывают ожидающие чтения; запросы с индивидуальными параметрами не объединяются. Краткие ссылки на рейсы берутся из transportOrders, без загрузки полной карточки на каждую строку.

Обычные уведомления закрываются через 3 секунды. При отказе в подтверждении рейса из-за запланированной смены собственника уведомление «Рейс не подтверждён» остаётся на экране до закрытия или повторной попытки. Текст указывает номер КТК и номер ожидающей заявки на смену собственника. При безномерном вывозе причина отказа появляется над списком КТК в форме отправки пакета.

Состав отчёта хранения, ссылки на заявки и поведение открытых/аннулированных периодов описаны в разделе «Хранение КТК» ниже.

## Редактор размещения КТК

В реестре накладных кнопка «Редактировать накладные» открывает простую таблицу: номер накладной, количество вагонов, количество КТК и маршрут. Детализация состава и фильтры отсутствуют. Накладные с нулевым количеством КТК доступны для выбора: их вагоны показываются пустыми карточками. Если у выбранных накладных нет и вагонов, выводится сообщение об этом; кнопка «Назад» возвращает к выбору. Без перемещений кнопка «Сохранить» недоступна, в том числе при открытии только пустых накладных. Несколько документов отмечаются галочками, переход к схеме — кнопкой «Далее». Выбор сохраняется между страницами, предел — 200 накладных и 200 вагонов. Затем показывается сетка физических вагонов с КТК и номерами их накладных. Один физический вагон отображается одной карточкой, даже если его КТК относятся к разным выбранным накладным. Все эти КТК показаны рядом на общей платформе; над каждым указан номер его собственной накладной. Вместимость проверяется по составу физического вагона только в выбранных накладных. КТК из разных выбранных накладных занимают свои места на платформе; свободная длина показана отдельной зоной. Невыбранные накладные и их КТК не отображаются и не учитываются при проверке. При переносе на карточку меняется только вагон: накладная переносимого КТК остаётся исходной, её номер над КТК не меняется. При обмене местами каждый КТК сохраняет собственную накладную. После переноса КТК отображается на карточке целевого физического вагона рядом с уже находящимися там КТК. Если физический вагон полностью опустел, остаётся пустая карточка, на которую можно вернуть КТК. Перенос между КТК внутри одного физического вагона не меняет данные и не включает сохранение.

Платформы и контейнеры отрисованы в CSS/SVG в единой синей палитре. КТК вытянуты горизонтально (пропорция около 2,5:1, минимальная высота сохраняет читаемость плотного состава). На экране от 1200 px отображаются четыре компактные карточки вагона в ряд; на более узких экранах — три, две или одна. КТК размещены в одной строке пропорционально длине: один 40FT на платформе 80FT занимает половину, свободная длина остаётся отдельной зоной для переноса. При превышении вместимости все КТК, включая шесть и более, сжимаются в пределах платформы и остаются доступными для перераспределения. Фиксированной пустоты над номерами накладных нет. На КТК показаны только тип 20FT/40FT сверху слева и номер слева по центру, с прежними рифлением и дверными штангами. Над КТК — номер накладной, под платформой — номер вагона с длиной в формате №42001073(40FT), без счётчиков и остальных характеристик. Перетаскивание на вагон перемещает КТК, на другой выбранный КТК — меняет их местами. Альтернатива для клавиатуры и сенсорного экрана: выбрать КТК кнопкой, затем свободную зону, номер вагона назначения или другой КТК. Выбор КТК не меняет высоту карточек и положение рядов. На схеме нет фильтров, шагов, общих счётчиков, подсказки по перетаскиванию и добавления вагона; в заголовке остаются «Назад», «Сохранить» и закрытие.

Промежуточное размещение может быть некорректным; такой вагон подсвечивается с объяснением, «Сохранить» недоступно до исправления. Общая дублирующая плашка под схемой не выводится. Тип и номер КТК расположены отдельными строками с отступом, без абсолютного позиционирования текста. Кнопки сброса перемещений нет; возвращение к выбору предупреждает о потере несохранённых изменений. Ошибка сохранения остаётся на странице, схема не исчезает; «Загрузить заново» явно предупреждает о потере несохранённых изменений. Ограничения и сохранение данных описаны в BACKEND_ALIGNMENT.md.

Регрессионные сценарии: [редактор и пустые накладные](scripts/waybill-placement-ui.cjs), [переполненная платформа и пропорции КТК](scripts/waybill-placement-length-ui.cjs), [геометрия таблицы КТК поставки](scripts/receiving-ktk-layout-ui.cjs). Перед запуском проверять окружение и предусмотренные каждым сценарием фикстуры.

## Хранение КТК

Раздел /container-storage расположен в «Отчётах». Основная строка — физический визит «Поставка → Вывоз»: номер КТК, общее число дней, даты и ссылки на обе транспортные заявки, их клиент/собственник, транспорт, перевозчик/отправитель/получатель и груз. Повторный receiving того же КТК показан отдельным визитом. До shipping поля его даты, заявки и реквизитов пусты. Номер КТК открывает историю; номера заявок без знака № открывают карточки. Источники — в [CONTAINER_STOCK.md](CONTAINER_STOCK.md#текущий-отчёт).

Стрелка в первой колонке раскрывает периоды собственников непосредственно под строкой визита в той же таблице. Заголовки единственные и находятся сверху: номер КТК, собственник, дни, начало/конец, события, заявки и реквизиты поставки/вывоза. Даты, дни и ссылки родительской и дочерних строк выровнены по одним колонкам. Родитель показывает собственника последнего действующего периода этого визита на дату расчёта (для завершённого визита — собственника на момент вывоза), итог визита и транспортные реквизиты; будущие передачи не меняют его до своей даты. Дочерние строки — собственника и его период по хронологии, без повторения транспортных данных. Визит выделен мягким фоном, дочерние строки соединены тонкой линией; отдельной вложенной таблицы и повторной шапки нет. Без передач внутри одна строка. День передачи входит в обе строки собственников. При нескольких передачах в один день каждый период владения включает этот день. В строке визита каждый календарный день считается один раз. Будущие назначения и будущие окончания скрыты до даты расчёта. Кнопка раскрытия имеет aria-expanded и доступна с клавиатуры. Прямая ссылка periodId показывает весь соответствующий визит, автоматически раскрывает его и выделяет выбранный период; сворачивание остаётся доступным.

Страницы содержат по 20 целых визитов; передачи одного визита не разбиваются между страницами. Счётчик показывает количество визитов. Раскрытие не меняет размер страницы и не запускает повторную загрузку. Раздел занимает высоту окна; заголовок, фильтр и пагинация остаются вне таблицы, обе прокрутки находятся внутри её рамки. Основной заголовок закреплён. Раскрытие сохраняет общую сетку колонок. На телефоне сохраняются колонки и учитывается нижнее меню.

При открытии раздела показывается форма. Подписи расположены над полями. Если ширины не хватает, поля и кнопки переходят на следующую строку. Номер КТК и период необязательны. При вводе букв или цифр поле «Номер КТК» предлагает номера с таким фрагментом в любой позиции, независимо от регистра. Можно выбрать номер из списка или сформировать отчёт по введённому фрагменту. Пустое поле означает «Все КТК». Кнопка «Период» открывает окно с месяцами выбранного года и полями «С» и «По» под ними. Один месяц заполняет обе даты его календарными границами. Второй месяц расширяет диапазон до двух выбранных границ, в том числе через границу года. Повторное нажатие на границу снимает её. Если обе границы уже заданы, нажатие на другой месяц начинает новый выбор. Даты можно ввести вручную. «Выбрать» переносит период в форму, а закрытие окна отменяет несохранённый выбор. «Сформировать» применяет выбранные условия, а с пустыми фильтрами показывает все визиты. Правка полей меняет результат после следующего формирования. «Сбросить» возвращает пустую форму. Применённые условия и страница сохраняются в URL. В отчёт попадает весь визит, если КТК находился в остатках хотя бы один день выбранного периода. Рабочий календарь обновляет периоды и итоги. Отмена shipping открывает последний период; отменённый receiving скрывает весь визит. При ошибке загрузки доступна кнопка «Повторить». После формирования отчёта за месяц или диапазон рядом с «Дней хранения» появляется «Дней хранения в периоде». Визит показывает число календарных дней пересечения с выбранным периодом. При раскрытии видны и периоды с нулевым пересечением. CSV выгружает по строке на период собственника независимо от раскрытия. В режиме «За всё время» в CSV 17 колонок, с выбранным периодом — 18. Сохраняются UTF-8 BOM и защита от формул.

## Проверка изменений UI

По затронутым сценариям проверять заполненный и пустой результат, ошибку, недоступное состояние, фокус, клавиатуру, редактирование и длинные значения. Размеры экранов: 1440/1024/640/360/320 px; отдельно масштаб 90% для таблиц. Проверять раскрытие групп, сохранение колонок и отсутствие переполнения страницы.

Запускать ESLint, Vitest, TypeScript/Vite при изменении frontend. Проверки с сохранением документов — только на отдельной тестовой БД. Просмотр рабочей системы для проверки не должен создавать или изменять данные.

## Отдельный просмотрщик БД

Диагностический интерфейс `db-viewer/public` доступен на localhost:3022 отдельно от MVP. Компоновка и плотность сетки приближены к тёмной теме DBeaver: плоские панели без крупных скруглений, компактные полосы инструментов, чередующиеся графитовые строки, серо-синие заголовки, светлый текст и тонкие границы ячеек. Закреплённая колонка номеров имеет отдельный серо-синий фон; при наведении строка выделяется приглушённым синим. Приглушённый синий акцент выделяет активную таблицу, вкладку, фокус, схему и ссылки между записями; большие поверхности имеют низкую насыщенность. Основной текст данных остаётся нейтральным, состояния и изменения имеют отдельную цветовую подсветку. Кнопка «Добавить таблицу» создаёт независимые панели без фиксированного ограничения количества. У каждой панели — выбор таблицы, поиск, сортировка, пагинация, вкладки «Данные», «Структура» и «ER-диаграмма» и закрытие; последнюю панель закрыть нельзя. Кнопки «Назад» и «Вперёд» над сеткой ведут по независимой истории переходов панели: из навигатора, списка таблиц или журнала. Возвращаются таблица, фильтр связи, поиск, сортировка, страница, размер страницы, выбранная вкладка и положение прокрутки сетки; данные перечитываются из БД. Новый переход после возврата удаляет прежнюю ветку «Вперёд». Автообновления и обычное редактирование фильтров не создают шагов истории; текущие настройки сохраняются при уходе. При отсутствии шага кнопка недоступна. История хранится до закрытия панели или перезагрузки страницы. Навигатор и журнал открывают таблицу в активной панели, обозначенной рамкой и подписью; щелчок или фокус внутри другой панели делает её активной. На любом экране панели расположены одной колонкой друг под другом, каждая занимает всю ширину области данных. При нехватке высоты доступна вертикальная прокрутка списка панелей. Под каждой панелью, включая единственную и последнюю, есть нижний разделитель: перетаскивание вверх/вниз меняет только её высоту, соседние сохраняют свои размеры и сдвигаются ниже. При нехватке места прокручивается список панелей. Разделитель доступен с клавиатуры: ↑/↓ — шаг 20 px, Shift — 80 px, Home/End — минимальная/максимальная высота, Escape отменяет текущее перетаскивание. Минимальная высота — 280 px, на узком экране — 360 px, максимальная — 5000 px. Кнопка «Выровнять высоту» или двойной щелчок по разделителю возвращает равные размеры. В шапке слева ручка ⠿ позволяет перетащить всю панель выше или ниже; подсвеченная граница показывает место вставки, у краёв экрана список прокручивается. На ручке ↑/↓ перемещают панель на одну позицию, Home/End — в начало/конец, Escape отменяет жест. Единственную панель перемещать нельзя. Порядок меняется без пересоздания панели: сохраняются таблица, данные, поиск, фильтр, сортировка, страница, история переходов, размеры столбцов и высота. Номера панелей остаются стабильными. Размеры и порядок сохраняются при обновлении данных и смене таблицы в текущей странице; при полной перезагрузке сбрасываются. Пауза и ручное обновление общие, события БД обновляют все открытые панели. Дерево БД → public → Таблицы имеет сворачиваемые ветви; справа — выбор текущей таблицы без дублирующего заголовка, переключение данных/структуры и сетка с тонкими границами ячеек. Тёмная палитра применяется также к поиску, спискам, журналу, диалогу записи, сообщениям ошибок и предупреждений; фокус и подсветка изменений различимы на тёмном фоне. Системные элементы используют color-scheme: dark. Строки данных высотой 26 px, текст данных размером 13 px в Segoe UI с табличными цифрами, числовые значения выровнены вправо, закреплённая колонка номеров позволяет открыть все поля записи в dialog с закрытием Escape. Ссылки внешних ключей обозначены небольшим синим значком ↗; текст значений остаётся нейтральным. Обычный щелчок по значению ссылки открывает связанную таблицу с точным фильтром в новой панели непосредственно под исходной; клавиши-модификаторы не требуются. Исходная таблица, поиск, сортировка, страница и история переходов сохраняются; новая панель получает собственную историю и обычный разделитель высоты. Кнопка «Последние изменения» расположена слева перед поиском; стрелка сортировки — перед названием колонки. Поиск, сортировка и пагинация располагаются непосредственно над и под сеткой; ниже — журнал событий с колонками времени, операции, таблицы и транзакции. Кнопка «Скрыть журнал» / «Показать журнал» в верхней панели освобождает место для таблиц; выбор сохраняется в браузере после обновления страницы. Скрытие не останавливает получение событий и не очищает историю. Состояние подключения и время обновления показаны в нижней строке состояния. Большой заголовок и отдельные карточки не используются. Поиск здесь является частью назначения инструмента. Ширина навигатора меняется перетаскиванием разделителя справа; выбор сохраняется в браузере. Границы — от 180 до 600 px с сохранением места для таблиц на текущем экране. Разделитель доступен с клавиатуры: ←/→ — 20 px, Shift — 80 px, Home/End — границы; Escape отменяет перетаскивание, двойной щелчок возвращает исходную ширину. На узком экране список таблиц расположен сверху, разделитель ширины скрыт, широкие данные прокручиваются внутри рамки. Обновление по событиям сохраняет выбранную таблицу, поиск и страницу; есть пауза, ручное обновление, состояние соединения и ошибка чтения. Новые и изменённые строки выделяются цветом. В оранжевой изменённой строке поля, отличающиеся от предыдущего показанного состояния записи, дополнительно выделяются более ярким янтарным фоном и нижней линией. Сравнение учитывает NULL и пустую строку; после смены фильтра, сортировки или страницы сравнение начинается заново. При следующем изменении состава или значений отображаемых записей все предыдущие отметки этой панели сразу сбрасываются: выделяются только новые строки и изменённые поля последнего обновления. Последовательное добавление записей не накапливает зелёную подсветку на предыдущих строках. Простое перечитывание без изменений сохраняет текущие отметки в пределах общего восьмисекундного окна подсветки строки. Ширина каждого столбца данных и структуры (кроме номера строки) меняется перетаскиванием правой границы заголовка до 1200 px. Минимальная ширина вычисляется по полному заголовку с учётом фактического шрифта, значка, места для стрелки сортировки и отступов (не менее 64 px). Сжать столбец уже названия атрибута нельзя ни мышью, ни клавиатурой. UUID изначально занимают эту минимальную ширину: длинный ID сокращается многоточием по границе ячейки и раскрывается при растягивании. Полное значение сохраняется в данных, подсказке при наведении и диалоге записи; переход по связи использует полный ID. Просмотрщик распознаёт одиночные и составные внешние ключи PostgreSQL: например, contract_id вместе с client_id и comprehensive_service_order_id вместе с клиентом и договором. В новой панели применяются все части ключа, соединённые условием И. Если поле участвует в нескольких связях, приоритет имеет ссылка на самостоятельно уникальное поле целевой таблицы, затем связь с меньшим числом полей (client_id ведёт к клиенту, contract_id — к договору, comprehensive_service_order_id — к комплексной услуге). Составная связь с NULL в любой части не отображается как ссылка. Ширины независимы для каждой панели, таблицы и вкладки, сохраняются при обновлении данных и переходах назад/вперёд в текущей странице. Двойной щелчок возвращает исходную ширину; ←/→ меняют её на 10 px, с Shift — на 40 px, Home/End задают границы, Escape отменяет перетаскивание. Перетаскивание не меняет сортировку; обновление данных во время жеста откладывается до его окончания. Названия атрибутов в заголовках сетки показаны шрифтом 14 px, без второй строки с типом данных. Типы данных доступны на вкладке «Структура». Рядом с именем атрибута показано «Примечание» — пояснение его назначения с переносом текста без обрезания. Описания берутся из комментариев PostgreSQL, а при их отсутствии — из проверенного по коду и документации словаря db-viewer/attribute-notes.mjs; для неизвестного поля явно указано отсутствие пояснения. Технические имена колонок сохраняются, поскольку инструмент предназначен для просмотра БД. Подключение, установка наблюдателя и проверки описаны в database/README.md.
