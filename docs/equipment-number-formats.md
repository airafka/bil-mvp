# Генератор накладных и демонстрационные данные

Параметры генератора сверены с кодом 16.11.2026. Генератор создаёт учебные данные локального MVP, а не импортирует реальные перевозки из ЭТРАН.

## Сценарий

UI: /waybills/generate. Ввод — количества КТК STANDARD_20 и STANDARD_40, суммарно от 1 до 200. Один запрос создаёт одну накладную, новые КТК и ЗПУ, использует подходящие свободные платформы или добавляет демонстрационные.

На вагоне размещаются **два КТК**, кроме последнего при нечётном общем количестве. Сначала распределяются КТК40: пары 40+40, при остатке — 40+20, затем пары 20+20.

| Состав | Минимальная длина платформы | Брутто при текущих параметрах генератора |
| --- | ---: | ---: |
| 20+20 | 40 футов | 26 400 кг |
| 40+20 | 60 футов | 36 400 кг |
| 40+40 | 80 футов | 46 400 кг |

Генератор проверяет и длину, и грузоподъёмность. Это отдельный алгоритм создания демонстрационного состава: в [редакторе размещения](../BACKEND_ALIGNMENT.md) ограничение вместимости определяется только длиной, а число мест и масса не проверяются. При отсутствии свободного подходящего вагона создаётся новый по совместимому справочному образцу с моделью. Если образца нет, запрос отклоняется и транзакция откатывается. Недостающие физические характеристики не вычисляются из номера вагона.

У нового КТК тара 3200 кг, нетто 10 000 кг для 20 футов и 20 000 кг для 40 футов. Грузоподъёмность справочной записи — 27 280 / 29 300 кг соответственно. Это заданные демонстрационные значения.

Накладная: Владивосток → Круглое поле (станции 1001 → 2001), плательщик ФИТ, груз «Пшеница» с кодом 011005, классификация «Неопасный груз», тип «Иностранное ЗПУ», по одному ЗПУ на КТК. Требуемые справочные записи должны существовать. Новая платформа получает демонстрационную дату ДР 15.06.2032; это не дата из паспорта реального вагона.

Код: [WaybillGenerationService](../backend/src/main/java/ru/billing/app/waybill/WaybillGenerationService.java), [форма](../frontend/src/pages/WaybillGeneratePage.tsx).

## Номера

| Объект | Текущая реализация генератора |
| --- | --- |
| Накладная | Свободный номер начиная с 1743125938 с пропуском занятых |
| КТК | Префикс TKRU, серия 900001–999999 и контрольная цифра |
| Платформа | Восемь цифр, начало 42, последняя — контрольная |
| ЗПУ | Семь цифр, начиная с 7000001; тип хранится отдельно |

Алгоритмы контрольных цифр находятся в [ContainerNumber](../backend/src/main/java/ru/billing/app/waybill/ContainerNumber.java) и [RailwayCarriageNumber](../backend/src/main/java/ru/billing/app/waybill/RailwayCarriageNumber.java). В генераторе есть проверка исчерпания учебных диапазонов.

Корректная структура номера не подтверждает регистрацию конкретной физической единицы, её собственника или сертификацию ЗПУ. Семизначный ЗПУ — демонстрационная схема MVP, не универсальная полная маркировка всех устройств. Учётные связи используют UUID.

## Происхождение справочных значений

Часть справочников была заполнена одноразовым [сценарием 03.11.2026](../scripts/fill-reference-demo-20261103.sql). Использовались демонстрационные грузоподъёмности и модели платформ 13-6851-01, 13-1223, 13-6903; даты следующего ДР в 2032 году были назначены по отдельному разрешению пользователя.

Это происхождение учебных данных, а не результат проверки паспортов конкретных КТК и вагонов. Существовавшие записи могут отличаться от параметров новых записей генератора. Их массы и техническую совместимость нельзя считать повторно проверенными только по наличию справочных реквизитов.

[Карта прежней замены номеров](number-format-mapping-20261103.json) сохранена как данные выполненной операции; она не задаёт текущий состав базы. Сценарии заполнения и перенумерации не повторять автоматически.

Проверки генератора создают накладные, КТК, вагоны и ЗПУ, поэтому выполняются только на отдельной тестовой БД. Перед отдельными изменениями рабочих данных необходима свежая резервная копия.
