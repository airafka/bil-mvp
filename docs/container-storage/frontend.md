# ТЗ для фронтенда. Отчёт «Хранение КТК»

Раздел «Отчёты» → «Хранение КТК», адрес `/container-storage`. Пользователь находит визит контейнера, видит длительность хранения на терминале и раскрывает её по собственникам. Повторная поставка того же КТК образует отдельный визит. На экране доступны просмотр, переходы к исходным документам и скачивание отчёта.

Обмен с сервером определён в [контракте OpenAPI](openapi.yaml). Источники данных, дата расчёта и правила учёта календарных дней описаны в [ТЗ для бэкенда](backend.md).

## Формирование отчёта

При открытии страницы без условий показать заголовок, поле «Номер КТК», поле «Период» со значением «За всё время» и кнопки «Сформировать» и «Сбросить». Загрузить варианты номеров КТК. Таблица, пагинация и ссылка на CSV появляются в процессе формирования отчёта и после получения результата, как указано ниже.

| Действие | Ожидаемое поведение |
| --- | --- |
| Нажать «Сформировать» | Убрать пробелы по краям номера, записать в URL `report=1` и заполненные условия. Запросить первую страницу визитов. При пустых полях показать все доступные визиты за всё время. Повторное нажатие с теми же условиями обновляет результат. |
| Изменить поля после формирования | Сохранить на экране результат последнего формирования. Новые значения применяются по кнопке «Сформировать». До этого ссылка на CSV использует прежние применённые условия. |
| Нажать «Сбросить» | Очистить форму и параметры URL, вернуться к начальному экрану. |
| Открыть ссылку с применёнными условиями | Восстановить поля и страницу из URL. Наличие `report`, заполненного фильтра или `periodId` запускает запрос визитов. `report=1` — параметр страницы FE. |
| Перейти из истории КТК по ссылке на период | Передать `periodId` в запрос визитов. Показать сообщение «Показан визит с выбранным периодом хранения.», раскрыть полученный визит и выделить строку с этим ID. Остальные периоды того же визита также доступны. Новое формирование снимает отбор по этому ID. |
| Изменить дату рабочего календаря | Обновить варианты КТК и уже сформированный отчёт на рабочую дату приложения. При смене условий, страницы или календаря исключить подмену свежего результата запоздавшим ответом на прежний запрос. |

### Номер КТК

- Получить варианты через `GET /api/container-periods/containers`. Подпись и значение выбора — `name` (номер КТК). В `query` передавать текст.
- Поле совмещает ввод и выпадающий список. При фокусе и вводе показывать номера, содержащие введённый фрагмент в любой позиции, без учёта регистра. Фильтровать уже загруженный список в браузере. Кнопка со стрелкой позволяет открыть полный список.
- При пустом поиске предложить «Все КТК». Это значение очищает отбор по номеру. При отсутствии совпадений показать «Совпадений нет». Пользователь может сформировать отчёт и по части номера, без выбора предложенного варианта.
- Вариант выбирается мышью либо клавишами ↑/↓ и Enter. Escape и уход фокуса закрывают список. У поля есть видимая подпись и роль `combobox`, у выпадающего списка — `listbox`. Обозначить раскрытие и активный вариант для средств доступности.

### Период

- Кнопка «Период» открывает диалог «Период хранения». В нём доступны двенадцать месяцев, переключение года и ручной ввод дат «С» и «По». При пустом выборе открывается год рабочего календаря.
- Выбор одного месяца задаёт его полные календарные границы. Второй месяц задаёт второй конец непрерывного диапазона, в том числе через границу года. Порядок кликов произвольный. Повторный клик снимает выбранную границу. При уже заданных двух границах клик по другому месяцу начинает новый выбор. Выбранные границы и промежуточные месяцы визуально различимы.
- Для ручного диапазона заполнить обе даты. Начало может совпадать с концом. Конец раньше начала и диапазон с одной датой нельзя подтвердить в диалоге. Обе пустые даты означают «За всё время».
- «Выбрать» переносит даты в форму. «Очистить» сбрасывает выбор внутри диалога. Закрытие крестиком или Escape сохраняет прежнее значение формы. Таблица обновляется по «Сформировать».
- Для одного полного месяца передать `month=YYYY-MM`. Для другого диапазона передать `storedFrom` и `storedTo` в формате `YYYY-MM-DD`. Для всего времени опустить эти параметры. Фильтр выбирает визиты, пересекающиеся с заданными днями, включая обе границы.

## Таблица визитов

Использовать `items` ответа `GET /api/container-periods/visits`. На один элемент приходится основная строка и раскрываемые строки из `periods`. Сохранить порядок визитов и периодов из ответа. Идентификатор группы — `visit.id`. Два визита с одинаковым номером КТК показываются независимо.

В первой служебной колонке разместить кнопку раскрытия. Далее вывести колонки в указанном порядке. В таблице ниже `первый` и `последний` означают первый и последний элементы `visit.periods` в полученном ответе, `p` — период соответствующей дочерней строки.

| Колонка | Строка визита | Строка периода |
| --- | --- | --- |
| Номер КТК | `containerName`, ссылка по `containerId` на историю | Пусто |
| Собственник КТК | `последний.ownerName` | `p.ownerName` |
| Дней хранения | `visit.storageDays` | `p.storageDays` |
| Дней хранения в периоде | `visit.storageDaysInPeriod` | `p.storageDaysInPeriod` |
| Начало периода (UTC) | `receivingAt` | `p.arrivalAt` |
| Событие | Поставка | По `p.startOrderType` |
| Заявка | `receivingOrderNumber`, ссылка по `receivingOrderId` | `p.startOrderNumber`, ссылка по типу и ID |
| Конец периода (UTC) | `shippingAt` | `p.departureAt` |
| Событие | Вывоз, если `shippingAt` заполнено | По `p.endOrderType` |
| Заявка | `shippingOrderNumber`, ссылка по `shippingOrderId` | `p.endOrderNumber`, ссылка по типу и ID |
| Клиент/Собственник поставки | `первый.receivingClientName` / `первый.receivingOwnerName` | Пусто |
| Транспорт поставки | `первый.arrivalTransport` | Пусто |
| Экспедитор/грузоотправитель поставки | `первый.arrivalParty` | Пусто |
| Груз поставки | `первый.arrivalCargo` | Пусто |
| Клиент/Собственник вывоза | `последний.shippingClientName` / `последний.shippingOwnerName` | Пусто |
| Транспорт вывоза | `последний.departureTransport` | Пусто |
| Экспедитор/грузополучатель вывоза | `последний.departureParty` | Пусто |
| Груз вывоза | `последний.departureCargo` | Пусто |

**Дни.** Колонка «Дней хранения» видна всегда. Колонку «Дней хранения в периоде» включать только для применённого месяца или диапазона. Использовать итог, полученный для соответствующего уровня. У визита день передачи учитывается один раз, у каждого из двух собственников входит в его период. Показывать и нулевое пересечение отдельного периода. Дата и время на экране — UTC в формате `ДД.ММ.ГГГГ, ЧЧ:ММ`. Сервер вычисляет дни по московским календарным датам.

**Реквизиты.** Пустые поля вывоза оставлять пустыми до фактического вывоза или после его отмены. Если имя собственника в колонке «Собственник КТК» отсутствует, показывать «—». Пару «клиент / собственник» формировать через пробелы вокруг слеша. При отсутствии обеих сторон ячейка пустая, при отсутствии одной на её месте «—». Для `VEHICLE` показать «Авто», для `RAILWAY` — «ЖД». Строки экспедитора и второй стороны, как и значения ЕТСНГ груза, выводить в готовом виде из ответа. Отсутствующее значение оставляет ячейку пустой. Несколько грузов сохраняются в одной ячейке, включая разделитель `; ` между значениями.

**Ссылки и раскрытие.** Номер КТК открывает `/container-owners/{containerId}/history`. Номера заявок показывать без префикса «№». Для `RECEIVING_ORDER` использовать «Поставка» и `/receiving-orders/{id}`, для `SERVICE_ORDER` — «Смена собственника» и `/service-orders/{id}`, для `SHIPPING_ORDER` — «Вывоз» и `/shipping-orders/{id}`. При отсутствии конечного события оставить его ячейки даты, типа и ссылки пустыми.

По умолчанию визиты свёрнуты. Кнопка раскрывает периоды сразу под визитом в той же таблице, в том числе единственный период визита без передач. Повторное нажатие сворачивает группу. Использовать общую шапку и выравнивание колонок. Визуально выделить строку визита и принадлежность периодов группе. Для кнопки указать действие, номер КТК и дату визита в доступном имени, состояние в `aria-expanded` и связь с раскрытыми строками в `aria-controls`. Для широкой таблицы обеспечить прокрутку внутри области таблицы с закреплённой шапкой и доступными фильтрами и пагинацией.

## Страницы, состояния и экспорт

- Запрашивать по 20 **визитов** с `page` от нуля. Показывать «Всего визитов» по `totalElements`, текущую страницу пользователю — от единицы, число страниц — по `totalPages` (минимум 1 для отображения). Кнопки «Назад» и «Далее» учитывают границы и загрузку. Если по ссылке открыта страница за последней, перейти на последнюю доступную, при пустом результате — на первую.
- При загрузке обозначить таблицу как занятую (`aria-busy`), показать статус «Загружаем данные…». Успешный пустой результат показывает «Визиты хранения не найдены» и нулевой счётчик. Ошибка результата показывает текст ошибки, кнопку «Повторить» и «Данные не загружены» в таблице. Сбой загрузки номеров имеет отдельное сообщение «Не удалось загрузить номера КТК.» и свою кнопку «Повторить». Текстовый ввод номера остаётся доступным.
- При успешном получении результата, в том числе пустого, показать ссылку «Выгрузить CSV» на `GET /api/container-periods/export`. Передать применённые фильтры без `page` и `size`. Для перехода из истории передать `visitPeriodId` с тем же значением, что `periodId` у запроса визитов. Это выгружает периоды всего выбранного визита.
- Пользователь получает серверный файл `container-storage.csv`. Экспорт охватывает все страницы, выдаёт одну строку на период и не зависит от раскрытия групп. За всё время — 17 колонок, с периодом — 18. В пустой выгрузке остаётся строка заголовков.

## Сценарии приёмки

| Условия и действие | Проверяемый результат |
| --- | --- |
| Открыть страницу, набрать `0460`, выбрать подходящий КТК или оставить фрагмент и нажать «Сформировать» | На вводе меняется список подсказок. После формирования в URL и запросе соответствующий `query`. Вывести все подходящие визиты, повторные заезды показать разными строками. |
| Сформировать отчёт по контрольному сценарию `TKRU9000460` за ноябрь и раскрыть визит | В колонке «Дней хранения в периоде» визит показывает **30**, прежний собственник **1**, новый **30**. Для режима «За всё время» колонка исчезает. |
| Выбрать день, который пересекает один из нескольких периодов визита | В основной строке пересечение равно 1. Раскрытие показывает все видимые периоды визита, включая периоды со значением 0. |
| Открыть визит одного ЖД-контейнера, у которого в накладной два разных груза | Например, при `arrivalCargo = "161128 — Лесоматериалы; 211009 — Уголь каменный"` вся строка видна в «Груз поставки». Новая строка периода при смене собственника сохраняет транспортные ячейки пустыми. |
| Открыть визит до фактического вывоза, затем посмотреть данные того же сценария после вывоза с другим грузом | У открытого визита реквизиты вывоза пустые. После вывоза у визита есть ссылка на заявку и собственный груз вывоза. Поставка по-прежнему показывает исходный груз. |
| Открыть период из истории и экспортировать CSV при свёрнутых и раскрытых строках | Ссылка из истории раскрывает нужный визит и выделяет период. Оба CSV содержат одинаковые строки всех периодов этого визита. |
| Открыть сохранённый URL, перейти на вторую страницу, изменить черновик фильтра, затем нажать «Сбросить» | URL восстанавливает применённые условия, результаты разбиты по визитам. Правка черновика сохраняет применённый результат и ссылку экспорта. Сброс возвращает начальную форму. |
| Проверить пустую выборку и раздельные ошибки списка номеров и визитов | Состояния различимы по сообщениям, повтор работает для нужного запроса. Управление номером, диалогом периода и раскрытием доступно с клавиатуры. |
