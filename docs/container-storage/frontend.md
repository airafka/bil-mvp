# ТЗ для FE основной системы. Отчёт «Хранение КТК»

В ALIS добавить страницу «Отчёты» → «Хранение КТК» (`/container-storage`). Пользователь находит физический визит контейнера, узнаёт срок хранения на терминале, раскрывает периоды владения и скачивает их в CSV. Каждая повторная поставка открывает отдельный визит.

## Подключение к API основной системы

В опубликованном снимке ALIS уже описаны поиск движений (`POST /containermovement/page`), история одного КТК (`POST /container/{id}/owner-history/page`) и выгрузка остатков в Excel (`POST /v2/report/containers-remains/download`). Готовую выборку визитов, сроки хранения и CSV добавляет backend по этому ТЗ. Для макета таблицы и проверки примеров можно использовать действующий отчёт bil-mvp. [Снимок API ALIS](../../openapi%20%281%29.yaml) · [Контракт работающего MVP](openapi.yaml)

Следующие три операции **предлагаются для ALIS**. Их пути заданы относительно базового адреса API основной системы. Все три вызывать штатным авторизованным HTTP-клиентом, отправляя JSON. Показывать пункт «Хранение КТК» пользователю с предлагаемым правом `ContainerStorage / READ`. Прямой переход на страницу подчиняется той же проверке. [Проект OpenAPI ALIS](alis-openapi.yaml) · [ТЗ для BE](backend.md)

| Действие | Запрос | Данные для интерфейса |
| --- | --- | --- |
| Загрузить номера при открытии | `POST /container-storage/containers/all`, тело `{}` | Массив `{id, code}`. Показывать `code`. Список включает контейнеры с завершёнными визитами. |
| Сформировать таблицу или сменить страницу | `POST /container-storage/page`, тело с `pageInfo` и `filter` | `content` — массив целых визитов с массивом `periods`. Метаданные находятся в `page`. |
| Скачать применённую выборку | `POST /v2/report/container-storage/download`, тело — сам объект `filter` | Файл `container-storage.csv`, тип `text/csv`. |

Для контрольного ноября тело первого запроса таблицы выглядит так (дата расчёта в примере задана явно).

```json
{
  "pageInfo": {"page": 0, "size": 20},
  "filter": {"query": "TKRU9000460", "month": "2026-11", "asOf": "2026-11-30"}
}
```

В ответе читать `page.number`, `page.size`, `page.totalElements`, `page.totalPages`. Для CSV того же результата отправить `{"query":"TKRU9000460","month":"2026-11","asOf":"2026-11-30"}`. В режиме «За всё время» без дополнительных условий для списка визитов передавать `filter: {}`, для выгрузки — `{}`. `report` и номер страницы в URL относятся к состоянию FE.

Обычный запрос можно отправлять без `asOf`. В этом случае сервер определяет дату расчёта по Москве. Если ALIS предоставляет общий рабочий календарь, использовать его дату в `asOf` для таблицы и для её выгрузки. Отображаемое время событий всегда переводить в UTC независимо от часового пояса браузера.

## Формирование отчёта

При открытии страницы без условий показать заголовок, поле «Номер КТК», поле «Период» со значением «За всё время» и кнопки «Сформировать» и «Сбросить». Загрузить варианты номеров КТК. Первый запрос таблицы отправляется по действию «Сформировать» или при открытии ссылки с применёнными условиями. При загрузке показать состояние таблицы, после успешного формирования — счётчик визитов, пагинацию и кнопку выгрузки.

| Действие | Ожидаемое поведение |
| --- | --- |
| Нажать «Сформировать» | Убрать пробелы по краям номера, записать в URL `report=1` и заполненные условия. Запросить первую страницу визитов. При пустых полях показать все доступные визиты за всё время. Повторное нажатие с теми же условиями обновляет результат. |
| Изменить поля после формирования | Сохранить на экране результат последнего формирования. Новые значения применяются по кнопке «Сформировать». До этого кнопка «Выгрузить CSV» использует прежние применённые условия. |
| Нажать «Сбросить» | Очистить форму и параметры URL, вернуться к начальному экрану. |
| Открыть ссылку с применёнными условиями | Восстановить поля и страницу из URL. Наличие `report`, заполненного фильтра или `periodId` запускает запрос визитов. `report=1` — параметр страницы FE. |
| Перейти из истории КТК по ссылке на период | Использовать новое необязательное поле `ContainerOwnerHistoryDto.storagePeriodId`. Показывать переход, если BE вернул это поле. Его значение записать в `periodId` URL и `filter.periodId`. Поле `id` самой записи истории идентифицирует событие. Показать сообщение «Показан визит с выбранным периодом хранения.», раскрыть полученный визит и выделить строку с этим ID. Остальные периоды того же визита также доступны. Новое формирование снимает отбор по этому ID. |
| Изменить дату рабочего календаря | Если в ALIS подключён общий рабочий календарь, обновить варианты КТК и уже сформированный отчёт на выбранную дату. При смене условий, страницы или календаря исключить подмену свежего результата запоздавшим ответом на прежний запрос. |

### Номер КТК

- Показывать `code` из ответа `POST /container-storage/containers/all`. После выбора номера или ввода его фрагмента передавать текст в `filter.query`. Справочник и список текущих остатков имеют другой состав, в том числе по уже вывезенным КТК.
- Поле совмещает ввод и выпадающий список. При фокусе и вводе показывать номера, содержащие введённый фрагмент в любой позиции, без учёта регистра. Фильтровать уже загруженный список в браузере. Кнопка со стрелкой позволяет открыть полный список.
- При пустом поиске предложить «Все КТК». Это значение очищает отбор по номеру. При отсутствии совпадений показать «Совпадений нет». Пользователь может сформировать отчёт и по части номера, без выбора предложенного варианта.
- Вариант выбирается мышью либо клавишами ↑/↓ и Enter. Escape и уход фокуса закрывают список. У поля есть видимая подпись и роль `combobox`, у выпадающего списка — `listbox`. Обозначить раскрытие и активный вариант для средств доступности.

### Период

- Кнопка «Период» открывает диалог «Период хранения». В нём доступны двенадцать месяцев, переключение года и ручной ввод дат «С» и «По». При пустом выборе открывается год рабочей даты, при отсутствии общего календаря — текущий год по Москве.
- Выбор одного месяца задаёт его полные календарные границы. Второй месяц задаёт второй конец непрерывного диапазона, в том числе через границу года. Порядок кликов произвольный. Повторный клик снимает выбранную границу. При уже заданных двух границах клик по другому месяцу начинает новый выбор. Выбранные границы и промежуточные месяцы визуально различимы.
- Для ручного диапазона заполнить обе даты. Начало может совпадать с концом. Конец раньше начала и диапазон с одной датой нельзя подтвердить в диалоге. Обе пустые даты означают «За всё время».
- «Выбрать» переносит даты в форму. «Очистить» сбрасывает выбор внутри диалога. Закрытие крестиком или Escape сохраняет прежнее значение формы. Таблица обновляется по «Сформировать».
- Для одного полного месяца в `filter` передать `month` в формате `YYYY-MM`. Для другого диапазона передать `storedFrom` и `storedTo` в формате `YYYY-MM-DD`. Для всего времени опустить все три поля. Фильтр выбирает визиты, пересекающиеся с заданными днями, включая обе границы.

## Таблица визитов

Использовать `content` ответа `POST /container-storage/page`. На один элемент приходится основная строка и раскрываемые строки из `periods`. Сохранить порядок визитов и периодов из ответа. Идентификатор группы — `visit.id`. Два визита с одинаковым номером КТК показываются независимо.

В первой служебной колонке разместить кнопку раскрытия. Далее вывести колонки в указанном порядке. В таблице ниже `первый` и `последний` означают первый и последний элементы `visit.periods` в полученном ответе, `p` — период соответствующей дочерней строки.

| Колонка | Строка визита | Строка периода |
| --- | --- | --- |
| Номер КТК | `containerName`, ссылка по `containerId` на историю | Пусто |
| Собственник КТК | `последний.ownerName` | `p.ownerName` |
| Дней хранения | `visit.storageDays` | `p.storageDays` |
| Дней хранения в периоде | `visit.storageDaysInPeriod` | `p.storageDaysInPeriod` |
| Начало периода (UTC) | `receivingAt` | `p.arrivalAt` |
| Событие | Поставка | По `p.startOrderType` |
| Заявка | `receivingOrderNumber`, ссылка по `receivingOrderId` | `p.startOrderNumber`, ссылка по типу и ID |
| Конец периода (UTC) | `shippingAt` | `p.departureAt` |
| Событие | Вывоз, если `shippingAt` заполнено | По `p.endOrderType` |
| Заявка | `shippingOrderNumber`, ссылка по `shippingOrderId` | `p.endOrderNumber`, ссылка по типу и ID |
| Клиент/Собственник поставки | `первый.receivingClientName` / `первый.receivingOwnerName` | Пусто |
| Транспорт поставки | `первый.arrivalTransport` | Пусто |
| Экспедитор/грузоотправитель поставки | `первый.arrivalParty` | Пусто |
| Груз поставки | `первый.arrivalCargo` | Пусто |
| Клиент/Собственник вывоза | `последний.shippingClientName` / `последний.shippingOwnerName` | Пусто |
| Транспорт вывоза | `последний.departureTransport` | Пусто |
| Экспедитор/грузополучатель вывоза | `последний.departureParty` | Пусто |
| Груз вывоза | `последний.departureCargo` | Пусто |

**Дни.** Колонка «Дней хранения» видна всегда. Колонку «Дней хранения в периоде» включать только для применённого месяца или диапазона. Использовать итог, полученный для соответствующего уровня. У визита день передачи учитывается один раз, у каждого из двух собственников входит в его период. Показывать и нулевое пересечение отдельного периода. Дата и время на экране — UTC в формате `ДД.ММ.ГГГГ, ЧЧ:ММ`. Сервер вычисляет дни по московским календарным датам.

**Реквизиты.** Пустые поля вывоза оставлять пустыми до фактического вывоза или после его отмены. Если имя собственника в колонке «Собственник КТК» отсутствует, показывать «—». Пару «клиент / собственник» формировать через пробелы вокруг слеша. При отсутствии обеих сторон ячейка пустая, при отсутствии одной на её месте «—». Для `VEHICLE` показать «Авто», для `RAILWAY` — «ЖД». Строки экспедитора и второй стороны, как и значения ЕТСНГ груза, выводить в готовом виде из ответа. Отсутствующее значение оставляет ячейку пустой. Несколько грузов сохраняются в одной ячейке, включая разделитель `; ` между значениями.

**Ссылки и раскрытие.** По `containerId` открывать историю КТК через штатную навигацию ALIS. Номера заявок показывать без префикса «№». По типу и UUID открывать соответствующую карточку основной системы. Подписи событий соответствуют типам `RECEIVING_ORDER` — «Поставка», `SERVICE_ORDER` — «Смена собственника», `SHIPPING_ORDER` — «Вывоз». Учитывать права на целевую карточку или историю. Если просмотр недоступен, показывать номер текстом. Если конечного события ещё нет, его дата, тип и ссылка остаются пустыми.

По умолчанию визиты свёрнуты. Кнопка раскрывает уже полученные периоды сразу под визитом в той же таблице, в том числе единственный период визита без передач. Дополнительный запрос при раскрытии не нужен. Повторное нажатие сворачивает группу. Использовать общую шапку и выравнивание колонок. Визуально выделить строку визита и принадлежность периодов группе. Для кнопки указать действие, номер КТК и дату визита в доступном имени, состояние в `aria-expanded` и связь с раскрытыми строками в `aria-controls`. Для широкой таблицы обеспечить прокрутку внутри области таблицы с закреплённой шапкой и доступными фильтрами и пагинацией.

## Страницы, состояния и экспорт

- Запрашивать по 20 **визитов** с `pageInfo.page` от нуля и явным `pageInfo.size = 20`. Показывать «Всего визитов» по `page.totalElements`, пользователю — номер `page.number + 1`, число страниц — по `page.totalPages` (минимум 1 для отображения). Кнопки «Назад» и «Далее» учитывают границы и загрузку. Если по ссылке открыта страница за последней, перейти на последнюю доступную, при пустом результате — на первую.
- При загрузке обозначить таблицу как занятую (`aria-busy`), показать статус «Загружаем данные…». Успешный пустой результат показывает «Визиты хранения не найдены» и нулевой счётчик. Ошибка результата показывает текст ошибки, кнопку «Повторить» и «Данные не загружены» в таблице. Сбой загрузки номеров имеет отдельное сообщение «Не удалось загрузить номера КТК.» и свою кнопку «Повторить». Текстовый ввод номера остаётся доступным.
- При ошибке 400 показать причину некорректного фильтра и сохранить поля для исправления. При 403 вывести штатное сообщение об отсутствии права, закрыть доступ к данным и выгрузке. Ошибка загрузки и успешная пустая выборка должны различаться.
- После успешного формирования, в том числе при пустой выборке, показать «Выгрузить CSV». По нажатию отправить в `POST /v2/report/container-storage/download` применённый фильтр, включая `periodId` при переходе из истории. В выгрузке `periodId` также выбирает целый визит. Тело свободно от `pageInfo`, номера страницы и оболочки `filter`.
- Получить успешный ответ как `Blob` и сохранить исходные байты под именем `container-storage.csv`. Сохранить UTF-8 BOM, кавычки и разделитель `;`, которые выставляет сервер. Ошибку запроса показать рядом с действием, сохранив таблицу и возможность повторить.
- Экспорт охватывает все страницы, включает одну строку на видимый период и не зависит от раскрытия групп. За всё время файл имеет 17 колонок, с выбранным периодом — 18. При пустой выборке остаётся строка заголовков.

## Сценарии приёмки

| Условия и действие | Проверяемый результат |
| --- | --- |
| Открыть страницу, набрать `0460`, выбрать подходящий КТК или оставить фрагмент и нажать «Сформировать» | На вводе меняется список подсказок. После формирования в URL и запросе соответствующий `query`. Вывести все подходящие визиты, повторные заезды показать разными строками. |
| Сформировать отчёт по контрольному сценарию `TKRU9000460` за ноябрь и раскрыть визит | В колонке «Дней хранения в периоде» визит показывает **30**, прежний собственник **1**, новый **30**. Для режима «За всё время» колонка исчезает. |
| Выбрать день, который пересекает один из нескольких периодов визита | В основной строке пересечение равно 1. Раскрытие показывает все видимые периоды визита, включая периоды со значением 0. |
| Открыть визит одного ЖД-контейнера, у которого в накладной два разных груза | Например, при `arrivalCargo = "161128 — Лесоматериалы; 211009 — Уголь каменный"` вся строка видна в «Груз поставки». Новая строка периода при смене собственника сохраняет транспортные ячейки пустыми. |
| Открыть визит до фактического вывоза, затем посмотреть данные того же сценария после вывоза с другим грузом | У открытого визита реквизиты вывоза пустые. После вывоза у визита есть ссылка на заявку и собственный груз вывоза. Поставка по-прежнему показывает исходный груз. |
| Открыть период из истории и экспортировать CSV при свёрнутых и раскрытых строках | Ссылка из истории раскрывает нужный визит и выделяет период. Оба CSV содержат одинаковые строки всех периодов этого визита. |
| Открыть сохранённый URL, перейти на вторую страницу, изменить черновик фильтра, затем нажать «Сбросить» | URL восстанавливает применённые условия, результаты разбиты по визитам. Правка черновика сохраняет применённый результат и условия экспорта. Сброс возвращает начальную форму. |
| Проверить пустую выборку и раздельные ошибки списка номеров и визитов | Состояния различимы по сообщениям, повтор работает для нужного запроса. Управление номером, диалогом периода и раскрытием доступно с клавиатуры. |
| Сформировать больше 20 визитов, раскрыть последний визит первой страницы, перейти на вторую | При раскрытии число запросов остаётся прежним. Следующий запрос содержит `pageInfo.page = 1` и прежний фильтр. Номер на экране — 2, счётчик отражает визиты. |
| Скачать отчёт за всё время, затем за ноябрь при условном фильтре `TKRU9000460` | Оба запроса используют авторизованный POST и соответствующий применённый фильтр. После чтения CSV с поддержкой кавычек у заголовка и каждой строки 17 и 18 колонок соответственно. Вторая выгрузка содержит «Дней хранения в периоде» на четвёртой позиции, оба собственника представлены. |
| Открыть историю КТК с двумя событиями, только у одного передан `storagePeriodId` | Переход доступен у этого события. Таблица и скачивание используют один и тот же `periodId`, UUID записи истории остаётся в карточке истории. |
| Получить 400 при открытии некорректной сохранённой ссылки, затем проверить прямой вход без `ContainerStorage/READ` | При 400 видна причина и доступно исправление фильтра. При 403 видна ошибка доступа, данные и CSV недоступны. |
